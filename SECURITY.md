# Reporting a security concern

Do not include credentials, private messages, database files, personal requester
details, exported records or live account screenshots in a public issue.

If GitHub offers private vulnerability reporting for this repository, use that
private channel. Otherwise, open only a minimal issue asking the maintainer for
a private reporting channel, without sensitive data or exploit details. Do not
assume ordinary repository issues are private.

Include the affected revision, a non-sensitive summary and a synthetic
reproduction when a private channel is established. Do not test a finding by
sending real mail, publishing records or weakening a live account's safeguards.

See [privacy and security design](docs/SECURITY.md) for the threat boundaries and
[testing limits](docs/TESTING.md) for what the automated checks do and do not prove.
